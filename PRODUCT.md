# Product context

## Register

product

## Users

Support operators handle customer conversations throughout a shift. Account administrators configure access and routing. Retention specialists need a shared workspace to find an existing conversation, contact the customer, finish a retention session, and revisit its saved history.

## Product purpose

Extend this Chatwoot installation with focused workflows while preserving its existing support operations. The retention design must keep customer messaging reliable, make responsibility visible, and keep retention activity separate from support automation and performance tracking.

## Brand personality

Familiar, direct, practical. Follow the existing Chatwoot application vocabulary and concise task-oriented copy. The user confirmed on 2026-09-29 that retention should use the existing layout, themes, composer conventions, and keyboard/accessibility behavior.

## Anti-references

Avoid a separate dashboard aesthetic, decorative reporting cards, a second messaging interface with different controls, and actions that change conversation ownership merely by opening a page. Avoid ambiguous send and completion feedback.

## Design principles

1. Make the next action and its consequence explicit.
2. Preserve familiar navigation and messaging behavior.
3. Enforce access and workflow boundaries on the server.
4. Preserve the operator's draft and explain recoverable failures.
5. Keep historical records readable and stable as live conversations change.

## Accessibility and inclusion

Use existing semantic controls, visible focus, keyboard navigation, and light/dark themes. Target WCAG AA contrast and keyboard operation for new surfaces; announce send, save, and error states without relying on color. Support narrow screens and reduced motion. Add English and Russian translations together, as required by AGENTS.md.

## Evidence

Context combines the user's confirmed retention brief with the existing account settings sections, sidebar, split conversation layout, message composer, and repository development guidelines. It does not assert that the current application has passed an accessibility audit.
